# Watchat — notes for coding agents

- Arabic first: every viewer-facing string has Arabic and English, Arabic is the default, layouts are RTL.
- WhatsApp messages go through `src/lib/whatsapp/messages.ts` (it enforces Meta's limits: 3 buttons, 20-char titles, 10 list rows). Never call the Graph API with hand-built payloads.
- Bot behaviour lives in `src/lib/bot/flow.ts` behind the `BotDeps` interface; add a test in `flow.test.ts` for every new branch.
- Visual-builder flows: `src/lib/flows/` is pure (types, engine, validate, sanitize, preview) and runs both in the bot and in the browser preview. Never import server code there. Saved flows always pass through `sanitizeGraph`; publishing requires `validateFlow` with no errors. Add tests in `flows.test.ts`.
- Every series chat runs through a flow; a series without one gets the standard flow auto-published (`src/lib/flows/standard.ts`). Bot texts marked `flowDefault` in `copy.ts` are only starting text for flow cards; the rest are Shared replies.
- Flows follow viewing: a viewer has one run per series (`flow_runs` keyed by viewer + series); episode cards skip what was watched (chat or web), links resume further ahead, the "On the web" entry fires from `/api/progress` (`src/lib/flows/web-trigger.ts`), and starting a series pauses other series' waits.
- Growth agent (`src/lib/growth/`): daily review of slipping viewers → suggestions the team approves in Admin → Growth agent (Suggest mode); autopilot unlocks only via `autopilotReadiness`. Only phone-free summaries go to the AI; every send goes through the messaging rules (opt-in, approved templates, quiet hours, 20 h cap).
- Database access is server-only via `db()` (service role). Never import `src/lib/supabase.ts` into client components.
- Never store raw phone numbers in events or logs; use `phone_hmac`.
- `wallet_ledger` is append-only: never update or delete rows.
- Schema changes: add a new file in `supabase/migrations/`, never edit an applied migration.
- Before committing: `npm test`, `npm run typecheck`, `npm run build`.
- Content CMS: series details (tagline, genres, tags, cast, age rating) and artwork slots (`src/lib/content-meta.ts`) live on the series page; flows reference them with `{source:"series", slot}` / `{source:"episode", episode}` media and `{tagline}` `{genre}` `{cast}` placeholders, so nothing is uploaded twice. Missing artwork falls back to the poster (`artUrl`). Artwork sizes come from one master (`ArtworkSlots`): a new upload or a saved artwork (`artworkAsMaster`, own storage hosts only); per size "Fill" (cut at the focus point) or "Whole picture" (master over a blurred copy), previewed before saving; geometry in pure `src/lib/artwork.ts` (tests in `artwork.test.ts`). WhatsApp versions of free episodes are compressed in the browser with ffmpeg.wasm (served from `/ffmpeg`, copied by the postinstall script).
- Coming back without messages: `/me` is the one fixed account address (same for everyone; the browser session decides whose account opens). `src/proxy.ts` renews the session cookie on each visit. The bot adds a one-time pin tip with the `/me` address to a viewer's first personal link (`viewers.pin_hint_at`), "حسابي" gets a sign-in link to `/me`, and Admin → Shared replies can put `/me` on the WhatsApp business profile (`src/lib/whatsapp/profile.ts`).
- Spend meter (`src/lib/spend/`): every outgoing WhatsApp message is logged in `wa_messages` with `source` (bot, flow, sequence, campaign, growth, admin) and `market` (never the phone); Meta's status webhook fills `billable` and `pricing_type`. Costs come from the rate card in `meter.ts` (overridable in Admin → Spend) via `wa_spend_groups`, with free ad windows and the 1,000 free service replies applied. "Pause marketing at the budget" is checked in `runner.ts` before every marketing template.
- CTR meters (`src/lib/ctr/`): messages and links carry `ref_type`/`ref_id`/`node_id` (sequence, campaign, flow card, growth); the `/w` route sets `link_tokens.opened_at` on the owner's first open, and flow button taps are `flow_tap` events. `ctr_messages` / `ctr_flow_cards` summarise them; Sequences, Campaigns, the Flow builder list and each canvas card show the meter with a verdict (`health`). Pass a `MsgRef` when you add a new sender.
- WhatsApp templates are one library (`wa_templates`, `src/lib/messaging/template-store.ts`): the Templates page and the flow builder's Template card use the same editor (`TemplateEditor`) and actions — `createTemplate` for new, `updateTemplate` for edits (Meta's edit endpoint for approved/rejected/paused, resubmit for drafts). `templateUsage` lists every flow (live + draft), sequence, campaign and growth use; templates in active use can't be removed.
- Brand & site (`src/lib/site/`, Admin → Settings → Brand & site, owner only): site address, names, logos, colours, support/business contacts (`site_settings`) and the Terms / Privacy / About pages (`site_pages`, simple safe text format rendered by `PageBody`). Use `await siteUrl()` for any public link (never `env.appUrl` directly; it is only the fallback). Colours reach the viewer site and admin as CSS variables from `brandCss` in the root layout; settings are cached for a minute (`clearSiteCache` on save).
- Sequence flows (Flow builder → Sequence flows, `/admin/sequences`, builder at `/admin/flows/sequence/[id]`): a `sequences` row holds the canvas (`draft`, published `graph`, `version`) and its trigger/delay/series, which publishing syncs from the Trigger card so `sequence_candidates` stays the single source of who enters. Cards: trigger, wait (≥1 h), condition (`came_back`, `paid_since`, …), template, end — `validateSequence` refuses anything free-form. `lib/messaging/sequence-flows.ts` runs them from the messaging cron (claims the moment in `sequence_sends`, one `sequence_runs` row per viewer + moment, waits resume on the 15-minute tick) and holds a sequence until every template on it is APPROVED. Sequences without a graph still run as single-template sequences.
- Shared replies flow (Flow builder → Shared replies, `/admin/bot`): one flow per tenant (`shared_flows`: draft, published `graph`, `version`) built on the same canvas. Cards: keyword ("Viewer sends" words, optional "anything else"), message, list (menu, ≤10 rows), link (resume), account, language, optin, condition (`has_series`, …), action (`opt_out`, `opt_in`, `delete_data`), choice, suggest; `validateShared` refuses the rest. Pure parts in `src/lib/flows/shared.ts` (`standardSharedFlow` rebuilds the built-in replies from saved texts and is what the bot runs until a tenant publishes; `matchKeyword`). The bot (`routeShared` in `flow.ts`) answers text intents menu/link/account/stop/delete/unknown and `s:<node>:<port>` taps from it; series codes, WATCH links and series-flow buttons never go there, and STOP / data deletion fall back to the built-in replies when no card has those words. Texts the bot sends by itself (unknown code, other series, picks, pin tip) stay in `bot_messages` (`FIXED_TEXT_KEYS`).
- Build with AI (✨ AI tab on all three canvases; `aiDraft` in `app/admin/ai-flow-actions.ts`, `lib/ai/flow-agent.ts`, pure `lib/ai/flow-draft.ts` + `lib/ai/learning.ts`): one step format for every canvas (`flowTool(mode)` limits kinds/checks to that canvas; `scriptIssues` uses the same validator as Publish). It learns per label and canvas kind: every draft is stored in `ai_flow_drafts`; the team's 👍/👎 + note (`rateAiDraft`) and, on publish, `recordPublished` → `draftEdits` (what they rewrote/removed/added) are signals; `learnLessons` folds them into ≤12 house rules in `ai_flow_lessons` (team-added rules are always kept and editable in the panel). Each draft prompt gets the rules, recent before→after rewrites and, for series flows, the best/weakest cards by CTR (`learnedPrompt`). Publishing runs the learning in `after()` so it never slows Publish.
- Viewer assistant (`/assistant`, also the home-screen app's start page; `src/lib/assistant/`, `POST /api/assistant`): helps signed-in viewers find series, search, see the preset offers (coin packs, season passes), continue watching and understand how Watchat works, nothing else. `engine.ts` is pure: chips, greetings, keywords, title/genre/cast search are answered without AI; only free text it can't place goes to AI (`ASSISTANT_TOOL`, Haiku, catalogue-only prompt) and the AI only classifies (intent, series codes, help topics) — every sentence shown is `TEXT`/`HELP` or catalogue data, off-topic gets a fixed reply. Limits: 20 messages / 10 min and 25 AI answers / day per viewer, plus `tenant_ai_settings.assistant_daily_limit` (separate from the team's monthly AI limit; usage purpose `viewer_assistant`). No conversation text is stored.
- Chat button: `ChatFab` (root layout) floats the assistant button on every viewer page, above the bottom nav when there is one; `chatFabHidden` keeps it off the watch feed (never interrupt watching), `/assistant`, admin, business and payment pages. It links to `/assistant?back=<page>` so the back arrow returns there.
- Web push / home-screen app: `app/manifest.ts` (start_url `/assistant`), `public/sw.js`, icons in `public/brand/`. `AlertsOptIn` shows iPhone users how to add Watchat to the home screen (iOS only allows web push from there) and turns alerts on (`/api/push` → `push_subscriptions`). VAPID keys are created per tenant on first use (`push_config`, private key sealed). `sendTemplate` in `runner.ts` sends marketing templates as web push first to viewers with alerts on (`push_config.push_first`, Admin → Spend), logging `push_messages`; WhatsApp only if no device accepts it. The 20 h marketing gap counts push too.
- Media on cards: every card that sends something can carry media (`MEDIA_KINDS`, `takesMedia` / `mediaOf` in `flows/types.ts`): message, language, link, choice, optin, list, account, suggest, template. Lists and the series list can't carry media in WhatsApp, so the engine sends it just before (`sendMediaFirst`); link, account and template are image-only (`IMAGE_ONLY_KINDS`); a Template card's image overrides the series banner for image-header templates (`headerImage` through `sendFlowTemplate` / `sendNamedTemplate`, also used for web push). The newer kinds keep `media` optional and omitted when empty. Sequence flows and Shared replies use the label-wide library (`media_assets.series_id` null, `sharedAssets`); series canvases see their own files plus the label-wide ones; deleting a file checks every canvas (`assetUsedAnywhere`).
- Watch page (`/watch/[code]/[episode]` → `components/watch/WatchFeed.tsx`): a full-screen vertical feed with one scroll-snapped slide per episode; scrolling moves to the next / previous episode and the address follows it (`history.replaceState`, so refresh, unlock and payments stay on it). Only the slide on screen mounts its video (`EpisodeVideo`: HLS, resume, progress heartbeat, 3-second auto-next). Back, coins, title, episode number and the Share / Info rail (inline-end: left in Arabic) fade out 3.5 s after the last touch (not while paused); a tap on the screen shows them and the next tap hides them; play / pause is the centre button that comes with them. Locked slides show the Paywall in place.
- Ping economy (`src/lib/economy/`): the viewer currency is Ping (بينج; `wallet_ledger`, `coin_packs` keep their names). `pricing.ts` is pure (markets, `quote`, promotions, check-in ladder, invite / partner codes, renewal retries); `store.ts` reads settings (`economy_settings`), `markets`, `market_prices` (item `pack:<id>` / `series_pass` / `weekly` / `yearly`, VAT included, per country; `ZZ` = rest of world) and resolves the viewer's market: IP country (`x-vercel-ip-country`, stored as `viewers.ip_country`) → phone country → ZZ. Never price in the browser: checkout always goes through `quoteFor`. Geo-fencing: `series.license_countries` (empty = everywhere) filters the web catalogue by `ipMarket()` and the bot by `storedViewerMarket`. Free Ping only through `grant_reward` (exactly once per key: welcome, checkin, referral, promo); paid orders through `fulfil_order`, then `afterPaid` (inviter reward after the friend's first purchase, partner commission). Weekly / yearly passes are `subscriptions` (`has_all_access` opens every series); they renew from the 15-minute cron (`billing.ts`, Tap saved card + payment agreement) only when `recurring_enabled` is on. Admin: Pricing & Ping (episode Ping, markets, price grid, packs, auto-renew) and Offers & promotions (rewards, promotions, partners). Add tests in `economy.test.ts`.
- Telegram (`src/lib/telegram/`, second chat channel): a Telegram viewer is an ordinary viewer whose address is `tg:<chat id>` (`phone_e164` "+tg:<id>", `phone_hmac` of "tg:<id>"), so `handleInbound`, flows, shared replies and every messaging sender work unchanged — `sendWhatsApp` routes "tg:" addresses to `sendTelegram`. `telegram.ts` is pure (update → InboundMessage, `/start CODE` → CODE, OutMessage → Bot API calls with inline buttons whose callback data is the WhatsApp reply id, site links as Mini App `web_app` buttons, `verifyInitData`); templates are rendered from the library as normal messages. `/api/telegram/webhook` (secret = `webhookSecret(token)`, dedupe in `wa_inbound` as `tg:<update_id>`), Mini App sign-in at `/tg` → `/api/telegram/auth`. Telegram Web / Desktop open the Mini App in a frame: viewer pages allow `frame-ancestors` telegram.org only (admin and business keep `'none'` + X-Frame-Options DENY), and a framed sign-in (`framed` in the auth body, `sec-fetch-dest: iframe` in the proxy) gets a SameSite=None + Partitioned session cookie (`sessionCookieOptions`); viewer APIs still refuse other origins (`sameOrigin`). On phones `TelegramMiniApp` (root layout, only inside Telegram) calls `expand`, `requestFullscreen` (Bot API 8.0+) and `disableVerticalSwipes`, and sets `--wc-tg-top` (safe area + Telegram's button row) so pages and the watch top bar stay clear of Telegram's Close / ⋯ buttons. Connect from Admin → Brand & site → Telegram (`TELEGRAM_BOT_TOKEN`). A trigger marks Telegram rows in `wa_messages` free. Telegram viewers pay in Telegram Stars (`telegram/payments.ts`): `payingMarket` gives them `STARS_MARKET` (XTR, no VAT) priced from `stars_prices` (Admin → Pricing & Ping), checkout returns an invoice link (`createInvoiceLink`, gateway `telegram`) opened with `openTelegramInvoice`; the webhook answers `pre_checkout_query` and fulfils `successful_payment` through `fulfil_order` + `afterPaid` (once per charge id). The monthly pass is a Stars subscription (30 days; renewals arrive as new payments → new orders; stop/restart with `editUserStarSubscription`, not the Tap cron). Admin → Orders → Refund Stars (`refundStarsOrder`). Signed-out screens follow the visitor's chat app (`visitorChannel`: the `wc_ch=tg` cookie set at Telegram sign-in, or Telegram's in-app browser) and offer "Sign in with Telegram" in Telegram blue (`TelegramSignIn`, `.wc-btn-tg`); a Telegram viewer's personal link that can't sign in goes to `/tg`, never the WhatsApp page. The dashboard splits users by chat app (`admin_channel_split`). Add tests in `telegram.test.ts`.
- Channels (WhatsApp / Telegram) on flows: `flows.channel`, `shared_flows.channel` and `sequences.channel` are `both` (default), `whatsapp` or `telegram`. A series (and the shared replies) has one `both` flow or a `whatsapp` + `telegram` pair: "Separate Telegram flow" (`splitFlow` / `splitShared`) copies draft + live version to a Telegram row and turns the original into WhatsApp's; "One flow for both" (`mergeFlow` / `mergeShared`) deletes the Telegram row. The bot resolves with `pickChannelFlow` (viewer's own app first, else `both`): `ensurePublishedFlow(tenant, series, viewerChannel)`, `publishedSharedFlow(tenant, viewerChannel)`; builders open a row with `canvasRow` (`?channel=telegram`). Sequences skip viewers of the other app (`runsFor`) and Telegram-only ones don't wait for Meta approval. Condition `on_telegram` works on every canvas; Template cards show what they do on each app (`CanvasChannel` context); CTR splits per app (`ctr_flow_cards_by_channel`, `ctr_messages_by_channel`, `channelStats`). Lists have All · WhatsApp · Telegram tabs (`ChannelTabs`). Add tests in `channels.test.ts`.
- File storage (`src/lib/storage/`): uploads get a target from `uploadTarget(key)` (server) and are sent with `sendUpload` (browser): pictures → Cloudflare Images (`imagedelivery.net/<hash>/<id>/watchat`, original format, variant created on first use), other files (WhatsApp videos, trailers, subtitles) → Cloudflare R2 (presigned PUT, public `R2_PUBLIC_URL`), full episodes → Stream; whichever isn't configured falls back to the Supabase "media" bucket. Saved paths are "cfimg:<id>", "r2:<key>" or a Supabase path (`providerOf`, `deleteStored`, `publicUrlFor` — never trust a URL from the browser). Admin → Brand & site → Storage shows what's connected and "Move existing files to Cloudflare" copies old Supabase files and rewrites every link with `replace_media_url` (scans all text/JSON columns except logs and the ledger). Add tests in `storage.test.ts`.
- Admin simplicity: the menu (`(panel)/layout.tsx`) puts day-to-day work first (Dashboard, Series, Viewers, Orders), then Money, with Marketing and Settings as fold-outs (`AdminNavLinks` `folded`; open on their own pages, Marketing open for the marketing role); every item has a plain `hint`. New series go through "Launch a series" (`/admin/series/new` → `/admin/series/[id]/launch?step=2…5`, `launch-actions.ts`): details → artwork → episodes (BulkEpisodes) → free episodes & price → licence, content check, publish. One pure checklist `readiness()` (`src/lib/admin/readiness.ts`) drives the series list's "Next step", the series page and both Publish paths; episodes without a web video stay hidden when a series goes live. Add tests in `readiness.test.ts`.
- Episode languages (`src/lib/storage/tracks.ts` pure, `stream-tracks.ts` server): one Stream video per episode in the series' original language (`series.dialect` holds a `LangKey`: ar, gulf, egy, lev, en, fr, tr, hi, ur, ko, es; `originalLang` maps old dialect values). Dubs (any language, Stream audio track labelled `LANGS[key].label`) and subtitles (WebVTT, keyed by tag ar/en/…; .srt converted in the browser) are stored and attached to that video (`episodes.tracks`: attached / pending / error; pending attach when the video id is saved or the series page opens). Naming rule for the content team (shown in the uploader, `NamingRules`): `EP07.mp4`, `EP07_audio_<code>.mp3`, `EP07_subs_<code>.srt`; `classifyFile` reads it (the language box turns red when missing). Player (`playbackLangs`): nothing extra when the video is in the viewer's language, else their dub (Arabic prefers gulf → ar → lev → egy), else their subtitles; one audio plays at a time (switching replaces the sound). hls.js tracks are chosen on AUDIO_TRACKS_UPDATED / SUBTITLE_TRACKS_UPDATED (subtitles applied after a tick) — verified with a real two-audio HLS stream in Chrome. Chat versions (`chatVersionPlan`): Arabic and English, using the original, else the dub as the sound, else (English only) burned-in subtitles. Add tests in `tracks.test.ts`.
- Dark viewer site: every viewer page uses the dark palette (`.wc` vars in `brand.css`, `:root` in `globals.css`; admin and business re-declare the light ones). Bottom bar: Home · Explore · Rewards (raised coral button) · My List · Profile (`BottomNav`); the wallet opens from the top-bar Ping balance and Profile. Home (`HomeScreen`): header (search, Ping, get Ping), Explore / New / Categories / Ranking tabs (`ExploreTabs` → `/explore?tab=`), hero cards (`BannerCarousel`: status, TOP #n, Watch now, HD · Eng Dub/Subs, bookmark, views, share), continue watching, trending (`TrendCard`), you might like (`LikeCard`). Popularity = distinct viewers starting an episode in 30 days (`series_popularity` → `views` / `rank`); My List bookmarks in `my_list` (`/api/list`, `toggleMyList`). Series page: episode chips (`.wc-eps`). Pure helpers in `catalogue-meta.ts`.
- Story series (Admin → Series → Story builder tab, `/admin/series/[id]/story`): `series.format` is `video` or `story` (+ `story_style`: visual_novel, chat, motion_comic, photo; `story_characters`). A story episode is scenes (picture or clip, voice, music, speaker, Arabic/English text, camera move, auto-advance) joined by routes: continue, choices (≤4; a Ping price makes one premium, paid once via `buy_story_choice`, always one free), branch on a flag an earlier choice set (any episode, `story_state.flags`), or end (optionally a named ending). Pure parts in `src/lib/story/` (types, sanitize, engine, validate; tests in `story.test.ts`); the builder saves `episodes.story_draft`, Publish runs `validateStory` and copies it to `episodes.story` (`story_ready` is generated from it and counts as "has content" in `readiness`/publish, like `stream_uid`). Scene files go to `<CODE>/story/` via `createStoryUpload`; links are always rebuilt from stored paths (`withUrls`). Viewers play stories on the web only (`/watch/<code>/<n>` renders `StoryWatch` → `StoryPlayer`, the same reader as the builder's preview); progress in `story_progress` + `progress`, choices through `/api/story/choice`, place and endings through `/api/story/progress`. Story series send no episodes in the chat (`wa_episode_count` 0). Import (`importStoryScript`, pure `story/import.ts`): paste the JSON from the story prompt (ChatGPT); characters merge, each episode becomes a draft; scenes keep their picture name in `ref` (`image_ref`), and "Match pictures by name" puts each uploaded `img_05.jpg` on every scene with that `ref` (`applyPicture`). A script may also carry a "media" list (picture name → file address, e.g. OpenArt results through the OpenArt connector): after importing, the builder calls `fetchStoryMedia` once per file, which fetches it only from allowed hosts (openart.ai and subdomains + `STORY_IMPORT_HOSTS`), checks type/size, copies it to Cloudflare (`copyToCloudflare`) and puts it on every draft scene with that `ref` (pictures → image, MP4 → clip; `applyMedia`). Tests in `import.test.ts`.
- Studio (Admin → Studio, `/admin/studio`; `studio-actions.ts`; pure `src/lib/studio/` stages, budget, bible, mcp; tests in `studio.test.ts`): story episodes produced with Claude (+ OpenArt) and reviewed before publishing. Stages (`studio_items`): brief → writing → script_review → pictures → final_check → approved → published; the team opens an episode with a brief, approves or sends back with a note (`moveStageAction`, notes thread), and publishes (`publishFromStudioAction` → `publishStory`, which also marks the Studio item published). Series bible (`series.story_bible`: style line, dialect, rules, character looks + portraits copied to Cloudflare; lock once approved). The Watchat connector for Claude is an MCP server at `/api/mcp` with the key in a request header (`x-api-key`, which Claude's connector form offers, or `X-Watchat-Key` / `Authorization: Bearer`; addresses `/api/mcp/<key>` work too (all keys sent are tried, `keyCandidates`; GET on that address says whether the key is valid); shared handler `studio/connector.ts`; unknown keys get 404, never 401, so Claude never starts OAuth) (keys in `studio_tokens`, hash only, 90 days, revocable; owner/content admins only; 300 calls/h): tools in `studio/tools.ts` (overview, get_series, get_episode, save_series_bible, save_episode_script, reserve_credits, attach_media, submit_for_review) with `STUDIO_INSTRUCTIONS`. Claude only works on episodes with a brief, writes scripts only at brief/writing, makes pictures only at pictures (after the script is approved), can never publish, and must `reserve_credits` before every OpenArt generation: estimates from `MODEL_RATES` (never below what Claude claims) against the monthly allowance and per-episode cap (`studio_settings`, owners set it), logged in `studio_credit_log`. Media goes through `copyStoryMedia` (`story/media-server.ts`, shared with the builder's import).
