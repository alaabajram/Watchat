# Watchat — notes for coding agents

- Arabic first: every viewer-facing string has Arabic and English, Arabic is the default, layouts are RTL.
- WhatsApp messages go through `src/lib/whatsapp/messages.ts` (it enforces Meta's limits: 3 buttons, 20-char titles, 10 list rows). Never call the Graph API with hand-built payloads.
- Bot behaviour lives in `src/lib/bot/flow.ts` behind the `BotDeps` interface; add a test in `flow.test.ts` for every new branch.
- Visual-builder flows: `src/lib/flows/` is pure (types, engine, validate, sanitize, preview) and runs both in the bot and in the browser preview. Never import server code there. Saved flows always pass through `sanitizeGraph`; publishing requires `validateFlow` with no errors. Add tests in `flows.test.ts`.
- Every series chat runs through a flow; a series without one gets the standard flow auto-published (`src/lib/flows/standard.ts`). Bot texts marked `flowDefault` in `copy.ts` are only starting text for flow cards; the rest are Shared replies.
- Flows follow viewing: a viewer has one run per series (`flow_runs` keyed by viewer + series); episode cards skip what was watched (chat or web), links resume further ahead, the "On the web" entry fires from `/api/progress` (`src/lib/flows/web-trigger.ts`), and starting a series pauses other series' waits.
- Growth agent (`src/lib/growth/`): daily review of slipping viewers → suggestions the team approves in Admin → Growth agent (Suggest mode); autopilot unlocks only via `autopilotReadiness`. Only phone-free summaries go to the AI; every send goes through the messaging rules (opt-in, approved templates, quiet hours, 20 h cap).
- Database access is server-only via `db()` (service role). Never import `src/lib/supabase.ts` into client components.
- Never store raw phone numbers in events or logs; use `phone_hmac`.
- `wallet_ledger` is append-only: never update or delete rows.
- Schema changes: add a new file in `supabase/migrations/`, never edit an applied migration.
- Before committing: `npm test`, `npm run typecheck`, `npm run build`.
- Content CMS: series details (tagline, genres, tags, cast, age rating) and artwork slots (`src/lib/content-meta.ts`) live on the series page; flows reference them with `{source:"series", slot}` / `{source:"episode", episode}` media and `{tagline}` `{genre}` `{cast}` placeholders, so nothing is uploaded twice. Missing artwork falls back to the poster (`artUrl`). WhatsApp versions of free episodes are compressed in the browser with ffmpeg.wasm (served from `/ffmpeg`, copied by the postinstall script).
- Coming back without messages: `/me` is the one fixed account address (same for everyone; the browser session decides whose account opens). `src/proxy.ts` renews the session cookie on each visit. The bot adds a one-time pin tip with the `/me` address to a viewer's first personal link (`viewers.pin_hint_at`), "حسابي" gets a sign-in link to `/me`, and Admin → Shared replies can put `/me` on the WhatsApp business profile (`src/lib/whatsapp/profile.ts`).
- Spend meter (`src/lib/spend/`): every outgoing WhatsApp message is logged in `wa_messages` with `source` (bot, flow, sequence, campaign, growth, admin) and `market` (never the phone); Meta's status webhook fills `billable` and `pricing_type`. Costs come from the rate card in `meter.ts` (overridable in Admin → Spend) via `wa_spend_groups`, with free ad windows and the 1,000 free service replies applied. "Pause marketing at the budget" is checked in `runner.ts` before every marketing template.
- CTR meters (`src/lib/ctr/`): messages and links carry `ref_type`/`ref_id`/`node_id` (sequence, campaign, flow card, growth); the `/w` route sets `link_tokens.opened_at` on the owner's first open, and flow button taps are `flow_tap` events. `ctr_messages` / `ctr_flow_cards` summarise them; Sequences, Campaigns, the Flow builder list and each canvas card show the meter with a verdict (`health`). Pass a `MsgRef` when you add a new sender.
- WhatsApp templates are one library (`wa_templates`, `src/lib/messaging/template-store.ts`): the Templates page and the flow builder's Template card use the same editor (`TemplateEditor`) and actions — `createTemplate` for new, `updateTemplate` for edits (Meta's edit endpoint for approved/rejected/paused, resubmit for drafts). `templateUsage` lists every flow (live + draft), sequence, campaign and growth use; templates in active use can't be removed.
- Brand & site (`src/lib/site/`, Admin → Settings → Brand & site, owner only): site address, names, logos, colours, support/business contacts (`site_settings`) and the Terms / Privacy / About pages (`site_pages`, simple safe text format rendered by `PageBody`). Use `await siteUrl()` for any public link (never `env.appUrl` directly; it is only the fallback). Colours reach the viewer site and admin as CSS variables from `brandCss` in the root layout; settings are cached for a minute (`clearSiteCache` on save).
